# 老师前端交互规划

本文是《作业批改多智能体-实施规格》的前端专章。实施时两者一起遵守。  
**只有老师一个角色。没有学生端、没有家长端、没有移动 App。** 学生拿到的是打印出来的答题卡。

默认实现：Streamlit 多页 + 全局底栏对话。布局与状态必须按本文，不能做成八个互不相通的 Tab。

---

## 1. 设计原则

1. **一班一上下文，一作业一对话。** 顶栏永远能看见当前班级、当前作业、当前阶段。换作业 = 换对话，禁止把两份作业的消息混在一个窗里。
2. **聊天和按钮走同一网关。** 页面上的「出卡」「导入名单」与输入框里说「帮我出卡」是同一条 `ask` / 工具调用。禁止两套逻辑。
3. **底栏对话全局常驻。** 老师在学情页问「谁连续薄弱」不必跳回对话页。流式打在底栏，结构化结果同时刷新当前页。
4. **无名单只允许闲聊。** 业务页可进，但主按钮禁用，点击或说话都返回同一句：「请先导入班级名单」。
5. **阶段可见。** 用顶栏阶段条，不要让老师猜下一步。阶段：未导入名单 → 未选题 → 已选题待出卡 → 已出卡待收回 → 批改中 → 待确认 → 已出学情。
6. **确认队列是打断。** 有待确认时顶栏红点，批改页/队列页可进，commit 长期画像按钮禁用直到队列清空或老师明确「先按已确认部分看学情」。
7. **可视化是学情的一等产出。** 学情页不能只有一段文字。备课页读 InsightPack，不展示扫描原图。
8. **桌面优先。** 最小宽度 1280。不为手机做第二套布局。
9. **本机工具气质。** 绑定 127.0.0.1，无登录也可先做（单老师）。不要做成 SaaS 营销站。
10. **禁止。** 人格标签、差生榜、预测高考分、一键发家长群、把 LLM 建议分标成「官方分」。

## 2. 壳层（所有页共用）

```
┌──────────────────────────────────────────────────────────────────┐
│ 作业批改    [班级 ▾]  [本次作业 ▾]  阶段：已出卡待收回   待确认(6) │
├────────┬─────────────────────────────────────────────────────────┤
│ 对话     │                                                       │
│ 名单     │                   主工作区                             │
│ 试卷     │                                                       │
│ 答题卡   │                                                       │
│ 批改     │                                                       │
│ 确认队列 │                                                       │
│ 学情     │                                                       │
│ 备课     │                                                       │
├────────┴─────────────────────────────────────────────────────────┤
│ 附件拖入区   说或点：出题 / 出卡 / 改卡 / 学情 / 备课     [发送]   │
│ 进行中：批改 12/50  S07  ████░░░░  可取消                         │
└──────────────────────────────────────────────────────────────────┘
```

### 2.1 顶栏

| 元素 | 行为 |
|---|---|
| 班级下拉 | 切换 `class_id`。无班级时显示「未导入名单」，点开即去名单页 |
| 作业下拉 | 该班作业列表，按时间倒序；「新建作业」清空当前 homework 开新对话 |
| 阶段徽章 | 只读，由会话状态推导，文案用规格里的六段阶段 |
| 待确认 | 数字 >0 时可点，跳转确认队列。0 时灰 |

### 2.2 左侧导航

八项固定顺序，与 Agent 同级思想对齐：**对话是网关，名单是门禁，后四项对应四个 Agent，确认队列属于答题卡 Agent 的人机环。**

| 导航 | 对应 | 无名单 | 无作业 |
|---|---|---|---|
| 对话 | 网关 | 可用 | 可用 |
| 名单 | 名册服务 | 主页面（空则引导上传） | 可用 |
| 试卷 | 作业生成 Agent | 禁用主按钮 | 可用（导入/生成即创建作业） |
| 答题卡 | 答题卡 Agent · generate_cards | 禁用 | 无题目结构则追问 |
| 批改 | 答题卡 Agent · grade_scans | 禁用 | 无模板则追问 |
| 确认队列 | 答题卡 Agent · review | 禁用 | 空态说明还没批改 |
| 学情 | 学情 Agent | 禁用 | 无已确认成绩则追问「请先收回扫描件批改」 |
| 备课 | 备课 Agent | 禁用 | 无 InsightPack 则引导先看学情 |

禁用 = 能进入看说明，不能提交业务。

### 2.3 底栏对话（全局）

- 多行输入，Enter 发送，Shift+Enter 换行。
- 支持拖入：xlsx/csv（名单）、docx/md（试卷）、png/jpg/pdf/文件夹（扫描件）。拖入后先显示附件芯片，发送时带上。
- 发送后：输入框锁定到本轮结束或用户点停止。
- 流式：token 追加在最新助手气泡；若是长任务，气泡内嵌进度条（`12/50`），与底栏进度条同步。
- 助手气泡可带「结构化动作卡」：例如「已生成 50 张卡」+ 按钮「去预览」。点了只跳转页面，不另调一次 Agent。
- 意图三分类在气泡上用小标签显示：`闲聊` / `单任务` / `闭环`，方便老师理解系统在干什么。不要把内部 Agent 名堆成调试日志。

### 2.4 进行中任务条

仅在 `working` 时出现：技能中文名、进度、当前学号、取消。取消走 A2A `tasks/cancel`。取消后主区回到取消前状态，聊天里留一条「已取消」。

## 3. 首次进入

未检测到任何班级时，主区全屏引导，导航仍在但业务项带锁。

**屏：导入名单（首次）**

- 标题：先导入这个班的学生，才能出卡和按人归档。
- 主操作：上传 CSV / XLSX，模板下载（`samples/roster.example.csv`）。
- 预览表：学号、姓名，行数，重复学号标红不可提交。
- 班级名输入（必填），确认导入。
- 成功：顶栏班级有值，自动进入对话页，系统消息：「已导入 N 人。下一步可以说『出一份二次函数作业』或去试卷页。」
- 次操作：「我先问问题」→ 进入对话，顶栏阶段仍是未导入名单，业务按钮继续锁。

## 4. 各页详细交互

### 4.1 对话

**目的：** 自然语言入口。普通聊天流式直出；业务由编排器派发。

主区：该作业的消息列表（一作业一对话）。无作业时是「未绑定作业的闲聊窗」，一旦出题/导入成功，把本窗绑定 `homework_id`，或提示「已开新作业对话」。

消息类型：

- 用户文本 / 用户附件
- 助手流式文本
- 追问卡：缺 1～3 项，每项一个输入或上传，提交后继续同一轮
- 结果卡：出题完成、出卡完成、批改摘要、学情三句提纲、备课提纲。各带「在xx页查看」
- 拒绝卡：无名单、要写入教务、要给学生贴标签。文案清楚，不装成功

空态：三句示例快捷芯片——「出一份高一二次函数课时作业并出卡」「导入这份卷子」「看看这班学情」。无名单时前两个芯片点了仍走门禁拒绝。

### 4.2 名单

**目的：** 硬门禁的可视化。

- 当前班学生表：学号、姓名。可搜索。约 50 行，不必分页，但要能滚动。
- 导入 / 追加 / 整班替换。追加遇重复学号：跳过并列出。替换要二次确认。
- 不提供「删除某学生并级联抹掉历史成绩」的一键按钮。若要纠正名单，只改正姓名；学号错误用「作废该学号并新增」说明，避免悄悄改历史。
- 导出当前名单 CSV。

### 4.3 试卷（作业生成 Agent）

**布局：** 左表单 / 右预览。

左：

- 模式切换：生成 | 导入
- 生成：科目、年级、作业名、知识点（多标签）、客观题数量、主观题数量、是否需要答案和评分点（默认要，否则 `gradeable=false` 黄条）
- 导入：上传 md/docx，解析后进同一预览
- 主按钮：生成试卷 / 解析导入。走 MCP edupaper-mcp 时显示「正在排版 DOCX」进度，不可假装瞬间完成

右：

- 题目列表：题号、类型、题干摘要、答案、评分点、知识点
- 可点开看全题。老师可改答案和评分点（改的是 MySQL items，不是只改聊天）
- 下载 DOCX / Markdown
- 状态：可出卡 / 缺答案不能机改客观题 / 缺评分点主观题全进队列

生成失败：保留表单，聊天和本页同时报错。禁止清空老师刚填的知识点。

### 4.4 答题卡（出卡 skill）

前置：有名单 + 有题目结构。缺一则说明缺什么，给跳转。

- 主按钮：生成本班答题卡（本地，无 LLM）。人数 = 名单人数。显示「正在出卡 1/50」
- 预览：默认看 S01 或名单第一人；可切学生。图上能看出学号、作业号、客观气泡、主观框
- 下载：单张 PNG、整包 zip、若有 PDF 则整班 PDF。页面上用只读字段展示打印文件路径（规格要求）
- 再次出卡：覆盖前提示「会替换本作业已生成卡，未收回的纸质卡将无法匹配新模板」

禁止：生成无名空白卡当正式发放。调试用的通用卡如果要做，必须标「仅调试，不可发给学生」。

### 4.5 批改（grade_scans）

- 上传：多图、pdf、文件夹。显示已收 N 张 / 名单 M 人
- 主按钮：开始批改。SSE 进度：当前文件、识别到的学号、客观完成、主观进队列数
- 结果总表：学号、姓名、客观分、主观建议分、待确认标记、缺卡
- 点一行：该生卡图、客观每题对错、主观切块图 + OCR 文本（只给老师看）
- 未匹配作业 ID 的图单独一列「无法识别」，不丢进别人成绩

批改中禁止二次点击开始。完成后若队列 >0，自动建议「去确认队列」。

### 4.6 确认队列

表格列：学号、题号、原因（学号无效 / 双涂 / 空涂 / OCR 乱码 / 低把握）、切块缩略图、建议分、老师分输入、采用建议、改分、暂不处理。

- 批量：全部采用建议分（需二次确认）
- 学号无效：下拉绑定到本班未交卡学生，或标为废卡
- 未处理完：学情页用黄条「含待确认，长期画像未写入」
- 全部处理完：出现「写入长期画像」——对应 `commit_long_term`，不是偷偷写

客观题像素结果在此只展示，不提供「改成另一选项」除非走明确的老师覆写并记 `source=teacher`。默认老师不改客观机改，避免把 OMR 原则改坏；若做覆写，必须留痕。

### 4.7 学情

**必须有图。** 两个 Tab：班级 | 个人。每个 Tab 再切：本次（short）| 长期（long）。

班级本次：

- 数字：均分、交卡人数/应到、待确认数
- 柱图：各知识点正确率，60% 处参考线，标题「本班各知识点正确率（已确认题）」
- 热力或表：学生 × 知识点，会/弱/未测，禁止用侮辱性色名当图例
- 讲评三句：全班先讲什么、单独看谁、下次补哪点（来自 InsightPack，可再问聊天润色但不能编造数据）

个人：学生下拉。错题列表、掌握条、与班级对比（正确率差）。长期：历次作业该生掌握变化折线。

无数据空态：请先批改并确认。不要画全 0 的假图。

### 4.8 备课

只读学情产物 + 生成文案。

- 下次讲课重点（自动带必讲知识点）
- 需要单独关注的学生学号（不是差生榜，标题用「建议单独看」）
- 学期规划：基于长期薄弱点的几条建议
- 主按钮：按这些重点生成下一份作业建议 → A2A 发给作业生成 Agent，成功后面板出现「去试卷页查看建议」，不在本页偷偷出完整卷除非老师到试卷页确认生成

老师可编辑提纲再保存（存的是备课文本，不改成绩）。

## 5. 作业阶段与页面解锁

| 阶段 | 对话 | 名单 | 试卷 | 答题卡 | 批改 | 队列 | 学情 | 备课 |
|---|---|---|---|---|---|---|---|---|
| 未导入名单 | 闲聊 | 主操作 | 锁 | 锁 | 锁 | 锁 | 锁 | 锁 |
| 未选题 | 开 | 开 | 主操作 | 锁 | 锁 | 空 | 空 | 空 |
| 已选题待出卡 | 开 | 开 | 开 | 主操作 | 锁 | 空 | 空 | 空 |
| 已出卡待收回 | 开 | 开 | 开 | 预览 | 主操作 | 空 | 空 | 空 |
| 批改中 | 开 | 开 | 开 | 开 | 进度 | 可进 | 锁 | 锁 |
| 待确认 | 开 | 开 | 开 | 开 | 开 | 主操作 | 可看含待确认 | 可读短包但标黄 |
| 已出学情 | 开 | 开 | 开 | 开 | 开 | 开 | 主操作 | 主操作 |

「空」= 能进页，主区说明缺什么。「锁」= 与空类似但更强调门禁。

## 6. 追问、拒绝、错误

追问卡最多同时 3 项，例如出卡缺作业名、客观题答案、名单（名单应已被门禁拦住）。填完继续原任务，不要让老师从零再说一遍。

拒绝（不可用表单补救）：写入教务、无评分点打精确官方分、给学生贴差生标签、发家长群。界面用拒绝卡，不生成假成功。

错误：文件格式不对、MCP 挂了、LLM 未配置。出题未配置 Key 时：允许导入，生成按钮说明「未配置模型，请改用导入」。主观批改无 LLM：全部进队列，界面写明，禁止随机分。

---

## 7. 流式与刷新

- 聊天 token：只更新当前助手气泡，不整页 reload。
- 出卡/批改进度：底栏 + 当前页进度；完成后刷新该页数据（卡预览、成绩表）。
- 学情图：批改确认或 commit 后刷新；不要每秒轮询图。
- Streamlit 若无法精细 SSE，最低标准：`st.status` / 进度条真反映 Redis 任务进度，聊天用流式回调。若 Streamlit 做不到底栏常驻，允许「对话页为家 + 其它页顶部一条约聊进度」，但发送入口每页都要有。

---

## 8. 组件清单（按此实现，禁止花活）

- 顶栏上下文、阶段徽章、队列徽章
- 左导航（八项）
- 全局输入条 + 附件芯片 + 进度条
- 消息：文本、追问卡、结果卡、拒绝卡
- 数据表（名单、题目、成绩、队列）
- 图片预览（卡、切块）
- 图表：柱状正确率、掌握热力/表、个人折线
- 上传区、确认对话框、禁用说明条

不要：营销轮播、暗黑主题切换（可跟随系统，但不是需求）、社交分享、多语言。

---

## 9. 验收剧本（前端必须能点完）

用规格第 19 节三人数据：

1. 首次进入 → 导入 `roster.example.csv` → 顶栏出现班级  
2. 对话或试卷页生成/导入最小卷 → 作业下拉有本次  
3. 答题卡页出 3 张 → 能预览、能看到路径  
4. 批改页上传夹具 → 进度 1/3… → S03 进队列、S02 主观 pending  
5. 队列页处理 → 学情页有柱图，不是空字  
6. 备课页能看到重点，点「建议下一份作业」后试卷页能接到建议  
7. 清空名单状态（或新库）说「帮我出卡」→ 拒绝文案与点按钮一致  
8. 闲聊「什么是等差数列」→ 不创建作业、不走出卡  

缺第 5 步的图或第 7 步两套文案不一致，视为前端未完成。
